# cmdterm-vt

The terminal emulator core of scriptschnell-term. It does no I/O and uses no unsafe code.

Modules:

- `parser`: the DEC ANSI state machine (Paul Williams' model) with colon subparameters,
  behind the `Perform` trait. OSC payloads reach the performer unsplit; `osc_split`
  splits them lazily, so dispatch never allocates.
- `utf8`: the streaming UTF-8 decoder the parser uses in ground state.
- `terminal`: `Terminal::new(Size, Config)`, `advance(bytes)`, and the core VT behavior
  (printing with xterm's pending wrap, cursor movement, erase, insert and delete, scroll
  regions and margins, SGR, charsets, alternate screen, DA and DSR replies).
- `screen`, `cell`, `style`, `color`: the model a renderer reads. Rows hold cells up to
  the last non-blank one and carry a sequence number that changes with every mutation.
  Cells hold one `char`, an interned style id and a width flag. Colors are
  `Default`, `Palette(u8)` or `Rgb`, resolved through a 256-entry `Palette`.
- `event`: bell, title and unknown OSC events, read with `drain_events`.

The terminal never writes to the program: replies go to a buffer read with
`take_replies`. The parser allocates nothing per byte. Printing, cursor movement, erase
and SGR allocate nothing once rows have reached the width in use.

Try it: `cargo run -p cmdterm-vt --example dump -- --rows 5 --cols 20 < file`.

Grapheme clusters are stored one per cell (`src/grapheme.rs`). Reflow of the screen and scrollback on a column change is in `src/reflow.rs`. xterm is the compatibility reference.

## Performance

`tests/alloc.rs` gates the hot paths: with a full scrollback and every style, link and
cluster seen once, plain ASCII, SGR output, TUI redraws, wide characters and clusters,
OSC 8 links, replies, events and the input encoders allocate nothing. A title change
still allocates, because `Event::Title` owns its string.

`cargo bench -p cmdterm-vt` (`benches/throughput.rs`) feeds streams (8 MiB in
4 KiB chunks, 24x80 screen, 10000 lines of scrollback, warm terminal) to this crate and
times a resize of a full scrollback. Pass a stream
name to run one: `cargo bench -p cmdterm-vt -- wide`.

Best of 7 passes, release profile, one machine. The wezterm-term column is history: the
bench compared against wezterm-term until it was dropped as a dependency, and the numbers
below are the last recorded run.

| Stream | cmdterm-vt | wezterm-term | Ratio |
| --- | --- | --- | --- |
| ascii lines | 500 MiB/s | 36 MiB/s | 14x |
| SGR (ls --color, compiler logs) | 137 MiB/s | 46 MiB/s | 3.0x |
| TUI redraw | 224 MiB/s | 16 MiB/s | 14x |
| wide characters and clusters | 53 MiB/s | 53 MiB/s | 1.0x |
| OSC 8 links | 315 MiB/s | 41 MiB/s | 7.7x |

The cmdterm-vt column was measured after the run scans below went in; before them it read
55, 79, 68, 53 and 137 MiB/s on the same machine.

### Run scans

`Parser::advance` finds runs of bytes that need no state change with a SIMD scan
(`src/scan.rs`): printable ASCII in ground state, OSC payload, and the body of SOS, PM,
APC and ignored DCS strings. The scans are safe Rust written so LLVM vectorizes them: a
16-byte chunk, one compare per byte, a bit mask and `trailing_zeros`, which becomes
`pmovmskb` with SSE2 on x86-64 and the NEON equivalent on aarch64. An ASCII run reaches
`Perform::print_ascii`, and the terminal writes it into the cursor row as one slice up to
the right margin, with one sequence number for the row. Anything the run path does not
cover (a waiting wrap, insert mode, a charset that maps ASCII, a cluster an ASCII
character could join) prints one character at a time as before.
`Terminal::advance_bytewise` skips both fast paths; `tests/props.rs` and
`tests/streams.rs` check that it ends in the same state as `advance`.

Reflow of 10000 scrollback lines (100 to 80 columns and back), per resize: 0.67 ms here,
14.5 ms in wezterm-term.

Machine: AMD Ryzen 9 8945HS w/ Radeon 780M Graphics, Linux, rustc stable, `cargo bench` defaults (thin LTO, one codegen
unit). Numbers vary by machine; the ratios are what the bench is for.

## Property tests

`tests/streams.rs` feeds generated byte streams from a weighted vocabulary of the supported
sequences (`tests/streams/vocab.rs`) and checks properties that need no second emulator: no
panics, the cursor and margins stay on the screen, one call and random chunking end in the
same screen, stable indexes stay monotonic and agree with the scrollback, and a narrowing
then widening resize keeps the invariants. `tests/props.rs` does the same for raw bytes.
`cargo test` uses a fixed seed. Raise the case count with `CMDTERM_VT_FUZZ_CASES`, for
example `CMDTERM_VT_FUZZ_CASES=100000 cargo test -p cmdterm-vt --release --test streams`.

wezterm-term was the oracle for a differential suite while this crate was written. The suite
and the dependency are gone. [`COMPAT.md`](COMPAT.md) keeps what it found: each intentional
difference from wezterm-term and from the xterm reference, with the sequence, both behaviours
and the xterm source it follows.

## Fixtures

`tests/fixtures/<name>/` holds recorded sessions of real programs: `meta.toml`,
`output.bin` (the raw bytes), `chunks.txt` (the read boundaries and resizes),
`snapshot.txt` (the golden final state). Differences to wezterm-term that were accepted when
the fixtures were recorded are in [`COMPAT.md`](COMPAT.md). `examples/record.rs` records them
from the scenario files, and `tests/fixtures/README.md` lists them and says how to record.
`cargo test -p cmdterm-vt --test fixtures`
replays every fixture in its recorded chunks and in random splits, and
`CMDTERM_VT_BLESS=1` rewrites the snapshots. CI never starts a program.
